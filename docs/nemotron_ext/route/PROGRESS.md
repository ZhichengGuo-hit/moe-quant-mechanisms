# E-R2 Nemotron 路由臂：结果

状态：完成（2026-11-18，24 条文本 = 8/域，`-ngl 20`，上游 llama.cpp 路由导出）。
判定：按精确匹配率（26.2% < 85%）记为 **P3**；但本臂的参照是 Q6_K 而非 BF16，
且 Q6_K 在 C4 的 GSM8K 上并不优于 Q3_K_M（0.97 vs 0.98），所以这一臂只能作
"路由对低比特敏感"的**存在性证据**，不能作为损伤方向的证据。

## 数字

- 模型层：23 个 MoE 层（52 个 block 中隔层为 MoE），128 专家，top-8。
- 24 条文本 / 1,621 token；两配置 token 序列逐位一致。
- top-8 精确匹配率 **0.2621** [0.2428, 0.2834]
- 平均 Jaccard **0.7839**
- 路由 JS 散度 **0.0865 bit** [0.0724, 0.1012]
- 翻转严重度中位数 17/23；≥12/23 层的 token 占 1398/1621；"完全不翻转"为 0。
- ΔNLL（Q3_K_M − Q6_K）：全体 **−0.0368** nats；按严重度分箱在 −0.11 ~ +0.03 之间，
  **没有** Qwen 臂那样的"严重度越高、代价越大"梯度。

## 解释

1. Nemotron 的路由对位宽更敏感：JS 0.086 bit 是 Qwen TCQ 臂（0.011）的 8 倍，
   但 Jaccard 仍有 0.78——同样是"集合换人、分布接近"的形态。
2. ΔNLL 为负（Q3_K_M 不差于 Q6_K）与 E-N1 的 C4 行为指标一致：该族在 3-bit 档
   没有质量塌陷。因此"路由敏感"没有转化为"任务代价"。
3. 与 C4 的"四档渐变"并置：M6 的结论保持"低比特敏感、无断崖"；路由层面的
   敏感性是"分布移动"而非"能力切换"。
4. 局限：Q6_K 非真值、仅 24 条文本、未做 BF16 参照（Nemotron 无 F16 GGUF 在库；
   若要补，需先转 F16，约 60 GB）。
