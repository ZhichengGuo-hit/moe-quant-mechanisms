# E-R2 Nemotron 并行臂（M6 路由诊断）

冻结时间：2026-11-18，在运行前写定。协议与 `../../route_consistency/PREREG.md` 相同，
差异只有模型与参照：

- **被测**：`Nemotron-Cascade-2-30B-A3B.i1-Q3_K_M.gguf`（18.49 GiB）
- **近无损参照**：`...i1-Q6_K.gguf`（31.21 GiB；BF16 参照不可得，Q6_K 作高锚）
- 文本：`tcq_exp/data/{math,code,general}_eval64.jsonl` 各取**前 8 条**（24 条）。
  这是对主臂的缩减（主臂 192 条）；原因：Nemotron 在 16 GB 卡上只能 `-ngl 20`，
  按 C4 实测约 25 s/题，24 条 × 2 配置约 10–15 min，可在一轮内完成。
  缩减只影响 CI 宽度，不改变判定线。
- 推理：llama.cpp 上游 `llama-route-dump`，`-ngl 20`、ctx 4096、batch 1024、
  关闭 MTP；两配置同二进制、同线程数。
- 指标与判定线：与主臂一致（精确匹配率 / Jaccard / JS / 翻转 token 的 ΔNLL）；
  主判定线 ≥95% 且无系统方向 → 路由不变；85–95% → 路由偏移；<85% → 限定语。
- 参照不是 BF16 而是 Q6_K：因此"一致率"是**下界**（Q6_K 自身也有量化误差），
  报告时须写明；若 Q6_K 自身的路由已与 Q3_K_M 不一致，只能说明"高比特与
  低比特路由不同"，不能完全归因于量化损伤。

## 判定衔接

- 若一致率 ≥95%：M6 的路由臂与 E-N1 的"四档渐变"一致——该族没有路由层面的
  不连续现象，M6 以"低比特敏感但路由稳定"关闭。
- 若 <85%：M6 的"模式切换"得到路由层面的支持（但 E-N1 的行为指标仍是渐变，
  两者需并置讨论）。
