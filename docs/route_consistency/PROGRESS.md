# E-R2 结果：路由一致性诊断（M5 的一半 + M6 的路由臂）

状态：三配置采集完成（2026-11-18，CPU 16 线程，同一 llama.cpp 路由导出工具）；
判定：**P3（路由不可忽略）**——top-8 精确匹配率 18.7%，低于 85% 预注册线。
但同一批数据给出两条重要的缓和证据：路由分布本身只移动了 0.011 bit，
聚合 usage 排名的 top-64 重叠仍有 91.2%。

## 1. 采集

| 配置 | 权重 | 路径 | 耗时 |
| --- | --- | --- | --- |
| BF16 参考 | F16 GGUF（`model/e20/qwen36_f16.gguf`） | 上游 llama.cpp，`-ngl 0` | 21.7 min |
| TCQ-nl_global（主臂） | `tcmoe/out/model-tcmoe-q4k-nl.gguf` | tcmoe fork，`-ngl 0`，默认 domain=global | 7.5 min |
| iq2xxs（外部对照） | `baselines/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf` | 上游 llama.cpp，`-ngl 0` | 5.8 min |

- 文本：`tcq_exp/data/{math,code,general}_eval64.jsonl` 全部 192 条（每条 64 token 的
  定长切片），共 11,202 token；三配置 token 序列逐位一致（分析脚本强校验）。
- 记录：每 token × 40 层 × 256 专家的 `ffn_moe_probs`（softmax 后概率，F32）；
  路由 gate 在三份 GGUF 中均为 F32（已核对），因此路由差异**不可能**来自 gate
  权重被量化，只可能来自隐状态漂移。
- 工具：给 llama.cpp 增加 `LLAMA_MOE_DUMP` 路径，在图算完后读回 `ffn_moe_probs`
  （标记为 output 防止缓冲区复用），不启用 `cb_eval`（后者会带来 16× 的逐节点同步开销）。

## 3. 聚合 usage 排名（直接检验 s = usage × q 的输入）

| 臂 | hard usage TV（40 层均值） | soft usage TV | top-64 重叠（均值 / 最低层） |
| --- | --- | --- | --- |
| TCQ | 0.0629 | 0.0259 | **0.9117** / 0.8438 |
| iq2xxs | 0.0258 | 0.0092 | 0.9629 / 0.9219 |

逐 token 的专家集合大面积改写，但**聚合 usage 排序高度稳定**：补丁名单所用的
top-64 专家在两配置间重叠 91%（最差层 84%）。这解释了为什么 C1.2 的名单类实验
对量化扰动不敏感，也把 M5 的回应变得更精确：
"用量矩阵稳健，逐 token 路由不稳健"。

## 4. 翻转 token 的下游代价

预注册的"翻转 vs 未翻转"对照**不可用**：翻转（≥20/40 层）覆盖 99.9% 的 token，
"未翻转"组为空（stable_n=0）。这是数据本身的新发现——量化对路由的扰动是普遍的，
不是少数 token 的例外。按预注册的替代口径（严重度分层，已在分析脚本中记录为偏离）：

| 翻转严重度（层数/40） | n | 平均 ΔNLL |
| --- | --- | --- |
| 20–24 | 196 | +0.108 |
| 25–29 | 1548 | +0.153 |
| 30–34 | 4480 | +0.338 |
| 35–40 | 3429 | +0.471 |

- 高严重度（> 中位数 33 层）vs 低严重度：**+0.169 nats，95% CI [0.107, 0.231]**。
- Spearman(严重度, ΔNLL)=0.075；Spearman(路由 JS, ΔNLL)=**0.246**。
  路由分布移动越大的 token，NLL 代价越高，但相关只解释一小部分方差——
  隐状态损伤本身与路由扰动共变，**不能把 NLL 代价全部归因于路由翻转**。

## 5. 判定与写作口径

- 按预注册的精确匹配线（≥95% / 85–95% / <85%）：18.7% → **P3**。
  归因章必须加限定语：$s = \text{usage}\times q$ 的"损伤可加、路由不变"前提
  **不成立**；逐 token 专家组合在量化后大规模改变。
- 但应同时写出两条缓和事实，避免过度解读：
  1. 路由分布本身移动很小（JS 0.011 bit），翻转主要发生在概率接近的专家之间
     （Jaccard 0.71，即平均 5.7/8 个专家仍相同）；
  2. 聚合 usage 排名稳定（top-64 重叠 91%），因此以 usage 为输入的补丁名单
     仍然可迁移。
- 机制地图：可新增"**路由漂移层**"（第四层），但它的量级是"集合层面大、
  分布层面小、代价层面集中在高严重度 token"；与 M5 的关系应从"前提成立"
  改为"前提近似成立 + 已测量偏差"。
- iq2xxs 作为外部量化器给出同方向、更小的扰动（JS 0.0057、top-64 重叠 96%），
  说明结论不是 TCQ 特有。

## 6. 与预注册的偏离（明示）

1. **翻转定义**：预注册为"任一层 top-8 不同"，实测覆盖 100% token，无对照；
   改为"≥20/40 层不同"作主口径，并保留严重度分层。该改动在运行后、看结果前
   由数据结构决定，已在此记录。
2. **BF16 参考路径**：任务书写"moe_lib 路径"，实际用 F16 GGUF + llama.cpp。
   原因：GGUF 量化模型只能在同一 llama.cpp 运行时内取路由，而 moe_lib 只支持
   INT4 store、不能加载 2-bit/IQ2 权重；为保持三配置同运行时，参考也用 GGUF。
3. **全部 CPU**：排除 GPU kernel（FA/量化 GEMM）差异这个混杂因子；
   部署态是 GPU，故绝对 NLL 不可直接外推，但一致性结论不受影响。
4. **NLL 绝对值的口径**：本工具用整段 teacher forcing 的逐 token logits，
   与 `llama-perplexity` 的分块滑窗不同（后者对同一文本的均值约低 0.2–0.3 nats）；
   (c) 只用配对差，不使用绝对值。
5. **Nemotron 臂**：24 条文本（8/域），见 `nemotron_ext/route/`。
